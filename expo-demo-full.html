ENTREPRENEURSHIP EXPO · STAFF & STUDENT MANUAL

Test it. Explain it. Demonstrate it.

Use this guide when you are presenting the Bubbles & Brew MVP to students, staff, judges or visitors. The recommended demonstration takes about five minutes.

01 · START HERE

The five-minute demonstration

Show two sides of the system: customer experience and operations experience.

CustomerDiscover services → book a wash → receive a booking reference.
OperationsFind the booking → progress the vehicle → complete the visit.
Expo MVP note: The current dashboard is a local demonstration environment. Bookings created in the browser are stored on that device until the secure Firebase staff/operations backend is activated. Be accurate when describing this.
02 · CUSTOMER TEST

Student or visitor: book a wash

Open bubblesandbrew.online. Show the Home page, Car Wash services, Café Lounge, Beauty Parlour, Monthly Plans, My Perks and Book section.

Say: “The car wash is the main business. The café and complementary services make the waiting experience more valuable.”

Use these demonstration values

FieldDemo value
VehicleToyota Harrier
RegistrationUAX 123A
Vehicle typeSUV
ServiceFull Wash
NameExpo Demo Customer
PhoneUse a designated test number where possible
Date / timeChoose a suitable demonstration slot
  1. Click Book a wash.
  2. Enter vehicle details.
  3. Choose Full Wash.
  4. Enter customer details.
  5. Choose the date and preferred time.
  6. Review the confirmation screen.
  7. Click Create booking.
Expected result: A booking reference such as BB-YYYYMMDD-XXXXXX is displayed. Keep it for the staff demonstration.
03 · STAFF TEST

Staff: run the operations queue

Open Operations Dashboard. Find the booking using its reference, customer, phone, registration or vehicle.

Demonstrate the workflow

REQUESTED→CONFIRMED→CHECKED IN→WASHING→READY→COMPLETED
StageMeaning
RequestedCustomer submitted a booking request.
ConfirmedStaff accepted the booking.
Checked inVehicle arrived and was received.
WashingVehicle is being serviced.
ReadyVehicle can be handed back.
CompletedVisit and handover are complete.

After Completed, point out the Completed and Revenue KPIs.

04 · WALK-IN

Demonstrate a customer who is already at the wash

Click + Walk-in booking. Enter customer name, phone, vehicle, registration, vehicle type, service, date, time and an optional note.

The booking starts as Checked in because the customer is physically present.

CHECKED IN→WASHING→READY→COMPLETED
05 · DASHBOARD TOOLS

Useful things to show

  • KPIs: bookings, requested, washing, ready, completed and revenue.
  • Search: booking number, customer, phone, registration, vehicle or service.
  • Date: Today or All dates.
  • Status: isolate a specific stage such as Washing or Ready.
  • Print: print the current queue.
  • Clear test data: reset the demonstration device between sessions.
06 · PRESENTATION SCRIPT

What to say to a judge

OPEN: “Welcome to Bubbles & Brew — Wash, Warm and Roll. Let me show you how a customer journey becomes an operations workflow.”

CUSTOMER: “I want to wash my Toyota Harrier.”

DEMO: Create the booking and read the reference aloud.

TRANSITION: “The customer has made the request. Now let's switch to the business side.”

OPERATIONS: Move it through Confirmed, Checked in, Washing, Ready and Completed.

CLOSE: “The same visit now has a customer-facing side and an operations side. This is the foundation we can extend into payments, staff roles, notifications, loyalty and reporting.”

What problem are we solving?

“We are turning a traditional car-wash visit into a connected customer experience. Customers can discover services and book digitally, while the business can manage the booking queue and vehicle progress. The café and complementary services turn waiting time into part of the experience.”

07 · TECHNOLOGY

If someone asks how it was built

  • Frontend: responsive web application.
  • Hosting: GitHub Pages.
  • Application logic: JavaScript.
  • UI: Bricolage Grotesque, Manrope and the Bubbles & Brew brand system.
  • Backend direction: Firebase / Firestore and Cloud Functions.
  • Expo MVP: browser-based local booking fallback plus operations dashboard.
Do not overclaim. Only describe a feature as production-connected after it has been activated and tested.
08 · SAFETY

Expo rules

Always

  • Use demo details where possible.
  • Tell visitors when they are in MVP mode.
  • Use a designated test number where possible.
  • Keep the dashboard on the demo device.
  • Reset test data when appropriate.

Never

  • Ask visitors for passwords.
  • Display another customer's private information.
  • Promise a production booking if the backend is not connected.
  • Enter sensitive information unnecessarily.
  • Delete real business data for a demo.
09 · TROUBLESHOOTING

If something goes wrong

Booking button does nothing

Refresh the page and use the main Book a wash button.

Booking is not visible on another device

Expected in local MVP mode. Use the same demonstration device.

Dashboard is empty

Create a customer booking on the same device or use + Walk-in booking.

Need a fresh demo

Use Clear test data, then create a fresh booking.

Website looks old

Open the site in a fresh/private browser window rather than repeatedly refreshing an old tab.
